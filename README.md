# qq-bot-suite

把 **DSH** 变成 QQ 机器人的插件：**启动 DSH，机器人自己就跑起来了。**

> 装了它之后，你只需要打开 DSH —— 守护进程会自动拉起 SnowLuma 和桥，不用再手动开一堆窗口。

---

## 它是什么

一个 DSH 插件，把下面这些揉进一个可安装的包里：

- **无感启动**：启动 DSH 就拉起守护 → 守护起 SnowLuma + 桥
- **可交互控制面板**：运行状态、响应档位滑条、白名单、用量计价、黑话库、微信开关、活动流
- **提示词看得见也改得动**：面板里能查「这一轮实际注入的全文」，也能直接编辑总提示词 —— 不用翻文件
- **首次配置向导**：自动找 SnowLuma、读账号、生成配置、装好 preset 和 MCP
- **完整的机器人能力**：群聊/私聊、表情、语音、看图、查资料、终末地数据查询
- **管理员私聊里能真干活**：在你自己私聊里，机器人可以读文件、改代码、跑命令（见下）

## 安装

### 方式一：从 GitHub 直接装（推荐）

1. DSH → **插件** → **添加插件**
2. 输入本仓库地址：
   ```
   https://github.com/Springwood925/qq-bot-suite
   ```
3. 点「安装」→ **完全退出 DSH**（托盘也要退）→ 重新打开

### 方式二：本地目录

1. 下载/解压本仓库
2. DSH → 插件 → 添加插件 → 粘贴解压后的目录路径
3. 重启 DSH

## 装完之后要准备的

| 需要 | 说明 |
|---|---|
| **一个 QQ 号** | **专门给机器人用的**，别用你的主号 |
| **QQ 客户端** | 在跑机器人的那台电脑上登录 |
| **SnowLuma** | 第三方协议端，**需要你自己下载安装**（本仓库不包含它） |
| **DSH 桌面版** | 0.2.0 以上 |

> SnowLuma 请从它的官方仓库获取。装好后**至少登录一次机器人 QQ**，让它生成账号配置。

## 首次配置

重启 DSH 后，插件页会出现一张 **「⚙ 首次配置」** 卡片：

```
① 已找到 SnowLuma：<自动检测到的路径>
   （找不到就给输入框，手填安装目录）

② 机器人账号：[你的机器人QQ（已配 OneBot）▾]

③ [你的 QQ 号（管理员）] [要接入的群号，逗号分隔]
```

填好 → 点 **「开始配置」** → 它会自动生成 `config.json` 并装好 DSH 的 preset 和 MCP。

**然后再重启一次 DSH**（让 MCP 生效），登录 QQ、让 SnowLuma 扫码，就完成了。

## 让机器人在私聊里干活（管理员专属）

在**你自己的 QQ 私聊**里，机器人不只是聊天 —— 它能像 agent 一样真干活：

```
你：读一下 E:\project\config.json 的前 20 行
你：把那个文件里 timeout 从 30 改成 60
你：跑一下 node --check src/bridge.js，看有没有语法错
你：在整个项目里搜一下 buildWakePrompt 出现在哪
```

它手上多了 7 个工具：读文件、写文件、精确替换、找文件、搜内容、跑 PowerShell、列目录。

### 安全边界（三层，别担心它乱来）

1. **只有你的私聊能用** —— 会话 key 必须严格等于 `private:你的QQ号`，任何群、任何别人的私聊调用都会被桥直接 403 拒绝，连水花都没有。
2. **危险动作要你点头** —— 覆盖已有文件、修改已有文件、删除/移动/停服/格式化这类命令，**不会直接执行**。它会先发一条：

   ```
   ⚠️ 我要修改已有文件
   将在 xxx.js 中替换 1 处
   预览：- 旧内容 / + 新内容
   回复「干」我就执行
   ```

   你回「干」（或"确认"/"ok"/"行"），它才会动手；5 分钟内有效。
3. **群聊完全够不着** —— 群里的机器人调这些工具会被拒，它自己也被告知"别在群里提、别尝试"。

### 注意

- 这个能力的本质是**把电脑的部分控制权交给机器人**。它只认你，但你也要盯着它做的事。
- 读 `config.json` 这类含令牌的文件时，桥的发送审计会把凭据遮掉 —— 它读得到、但发不到 QQ 上。这是故意的。
- 想关掉？删掉桥源码里 `src/agent-exec.js` 的引用或把 `socialV2.tools` 对应项置 false 都行，最省事是别在私聊让它干这类活。

## 面板里的两个提示词卡片

### ① 提示词注入（看）

选一个会话 → 点「拉取」，就能看到**机器人这一轮实际收到的全文**：人格、记忆、表情策略、沉睡等待、唤醒原因，全在里面。

- 标注来源：`实际注入 · <唤醒原因>` 表示这是真实发送前抓的快照；`预览` 表示这个会话还没被真实唤醒过（桥刚重启时是这种）。
- 字数、时间、可复制。
- **会话令牌自动遮掉**（面板可能被截图）。

### ② 总提示词（改）

直接编辑 `我的提示词.md`，保存即生效 —— **不用重启桥**（桥每轮现读这个文件）。

- 编辑的是**原文**（含 `<!-- -->` 注释），不是注掉注释后的版本，所以注释不会丢。
- 顶部显示 `注入 X 字 / 原文 Y 字`（注释不注入，两个数会不一样）。
- **每次保存前自动备份**到 `我的提示词.md.bak-<时间>`，最多留 5 份。
- 有未保存改动时会出现黄标「未保存」。

> 改动面板后（前端或 host 任一部分）都需要**重启一次 DSH** 才生效 —— 插件的 `client.js` 刷新页面就能换新，但 host 端（`lib/index.js`）必须重启。两边不同步时新端点会 404。

## 常见问题

**Q：首次配置卡片没出现？**
A：它只在「还没配置」时显示。配好后自动消失（正常）。

**Q：找不到 SnowLuma？**
A：点「重新检测」；还不行就在输入框里手填 —— 那个目录里应该有 `index.mjs` 和 `node.exe`。

**Q：账号下拉是空的？**
A：SnowLuma 还没登录过 QQ。先登录一次，再点「重新检测」。

**Q：配完了但机器人不回话？**
按顺序查：
1. `:3000` / `:3001` 有没有在监听（SnowLuma 起没起）
2. `:3100` 有没有在监听（桥起没起）
3. 桥日志里有没有 `DSH 已就绪`
4. SnowLuma 日志里有没有 `[Hook] login detected`（没有 = 没注入）

**Q：怎么停掉机器人？**
关掉 DSH 后，双击 `bridge/停止QQ机器人.vbs`。

## 目录结构

```
qq-bot-suite/
  ├─ lib/index.js           host 插件（检测 + 配置生成 + 端点）
  ├─ client.js              面板 UI（React）
  ├─ cordis.patch.yml       DSH bundle 声明
  ├─ package.json
  └─ bridge/                机器人本体
       ├─ src/              全部逻辑（唤醒判定/发送/控制台 API/…）
       ├─ public/           控制台页面
       ├─ scripts/          安装与测试脚本
       ├─ dsh/agent-presets/ DSH 的 agent preset
       ├─ roles/            角色卡
       ├─ 我的提示词.md     人格与行为约束
       ├─ config.example.json
       └─ qqbot-guard.vbs   守护进程
```
