# 记忆数据库维护

记忆保存在本机 `state/memory-tree.sqlite`，不随代码发布。SQL 语句缓存最多 128 项，只缓存编译后的语句，不缓存查询结果；纠正、遗忘和新记录仍立即读到当前内容。

SQLite 原有 WAL 自动检查点保留。额外维护每 10 分钟检查一次，WAL 达到约 4MB 时尝试 TRUNCATE 检查点；存在占用中的读事务时立即退让，下次再试，并恢复连接原来的 busy_timeout。不会靠删除 WAL 文件清理数据。数据库关闭时也会尝试检查点。WAL 大于主库本身并不表示损坏，大小也可能是可重复利用的空间。

重复观察相同人物、昵称和时间时不再执行无变化的写入。短时间内连续提交的新记忆合并触发后台索引任务，关闭时取消尚未执行的定时器。记忆内容、来源、版本、关系、遗忘屏障与召回预算保持原规则。

没有自动删除、按条数淘汰或静默归档。长期保留的有效记忆会随使用增长；需要清理时请在管理页核对后操作。归档会改变自动注入，不能当作保持召回不变的清理方式。

验证：`npm run test:memory`。测试使用临时虚构数据库，覆盖语句复用、缓存边界、无变化写入、读者占用时退让、定时维护、遗忘和会话隔离。
