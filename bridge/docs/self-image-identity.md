# 自身虚拟角色形象识别

读图时，将本次收到的静态图片放在前面，管理员在本机确认的参考图放在后面，同一次视觉请求做对照。不新增一轮独立聊天任务，不把参考图作为消息图片返回，也不改变原图、消息编号或发送权限。

`self_identity.verdict`为`self`（含自身形象）、`not_self`（不是自身形象）、`uncertain`（无法确定）。多角色画面用`subject`说明位置。它只判断虚拟角色，不据此识别现实人物。

- 完全相同的已确认图片，用二进制SHA256确定归属。缩放、压缩、裁剪后的新文件通过视觉对照判断，不把近似指纹当确定结论。
- 新图确认自身需要至少两组不同的已登记特征、至少一项独特结构特征、真实自身参考ID，且没有冲突和未解决的不确定性。只有蓝发、眼睛颜色或同款服装不足以确认。
- 明确排除需要可解释的矛盾；看不到尾巴、遮挡或裁剪不能直接当作不是自身的证据。换衣服、动作、表情或Q版比例允许变化。
- 参考图更新、特征更新、关闭功能及识别策略变化都会改变缓存标识。旧的普通看图缓存不会覆盖新识别。
- 视觉失败时，只能保留完全相同的已确认文件匹配，并明确未分析其他画面与文字。不缓存失败降级结果，后续可正常重试。

## 管理员配置与新增参考

在桥接根目录建立`self-identity.json`。可复制`self-identity.example.json`，填写自身角色的特征组合。参考图只允许位于本桥接的`assets/`内，限定PNG/JPEG/WebP、最多四张、每张20MB；要求管理员确认标记与正确文件指纹。文件被替换但清单未更新时，不再使用该库作确定判断。

管理员可在本机运行：

```
node scripts/enroll-self-reference.mjs --root . --image ./我的参考图.png --id chibi-front --kind self --caption 已确认的Q版正面形象
```

容易混淆、且已明确不是自身的角色，可用`--kind not_self`登记反例。清单中至少保留一张自身参考图；不允许同一图片重复登记或同时作为正反例。此脚本不作为群聊工具暴露；收到的图片、用户自称和模型判断不会自动登记。再次登记前需由管理员人工核对。

图库每次读图现读，无需因新增参考重建会话。关闭时将`enabled`设为false。没有可用库时，普通读图继续，身份结论保留为无法确定。

视觉判断是推断，不能承诺所有同人、模糊图片或变体都正确。应持续用未见过的自身变体与相似其他角色检验误认和漏认；不要把单个模型给出的自评分数当作经过校准的准确率。
