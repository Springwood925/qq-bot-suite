# 低频表达回顾（0.3.1）

这项功能让现有表达候选机制有机会实际运行。设计参考 [dsh-world 的每日回顾](https://github.com/chenkezhen480/dsh-world/blob/bf7e1e1337918bd9e32045927e8811649d8578a6/templates/alarm.md#L27-L32)，复用本项目的会话隔离、来源、版本和人工审核能力。

## 何时回顾

首次接入为现有消息建立基线，不扫描升级前的旧聊天。之后，仅在原本已经发生的二代唤醒中，当前可见窗口包含至少 12 条新的收到消息和 3 条自己的回复时，才可能附加一次简短回顾。窗口与正常聊天共用，不额外复制聊天全文，不额外主动唤醒或启动独立模型。

每会话滚动 24 小时最多一次，全局最多两次；存在待审核表达候选时暂缓。已取消、失败的安排也占额度，避免反复触发。记录最多保留每会话最近 50 次。只处理有稳定 QQ 身份的群聊/私聊；当前角色未启用情绪与目标机制、独立人格覆盖、记忆工具关闭或可见上下文关闭时，桥接不安排此回顾。

桥接原有暂停、白名单、发送、等待与收尾条件保持原规则。回顾要求模型先完成本次交流，有空再处理；失败则跳过，不为回顾反复取历史、重试或继续聊天。

## 模型怎样报告结果

回顾只检查自己的语境承接、解释长度、追问、指向、玩笑和拆消息方式。最多提出两条 100 字以内的原则，每条需引用本批至少 3 条收到的消息及 2 条自己实际回复。服务器核对消息序号、身份、时间、消息 ID 和正文哈希，拒绝跨会话、换掉的消息和已失效来源。

使用兼容入口 `qq_memory_append`，`category: activeTopic`，`content` 为以下 JSON 字符串：

```json
{
  "_memoryTree": 1,
  "action": "review",
  "reviewId": "使用本次唤醒提供的真实回顾ID",
  "candidates": []
}
```

空数组表示没有明确可改进之处，是正常结果。有候选时，每项给出 `content`、`sourceSeqs`、`selfSeqs` 和 `criterion`；criterion 为 `context/length/question/reference/humor/splitting` 之一。key 和 token 使用当前会话值。此协议通过现有 JSON 入口兼容旧 MCP 连接，不要求重建当前 QQ 会话。

候选不应包含人物称呼、账号、凭据或私事。重复原则不会重复写入，整批写入有事务保护。提交具有幂等性，重复提交不会重建已遗忘的候选。

## 怎样生效与关闭

DSH 插件详情页 → 记忆树 → 表达习惯，查看回顾状态和候选。`已安排` 不表示模型已经完成；`已报告回顾完成` 仅表示提交了结果，不证明聊天质量改善。候选必须由管理员确认，才成为当前会话的一条有限表达参考；不自动改写人格、不替代固定规则或增加工具权限。

检索诊断中的“低频自动表达回顾”开关可以关闭此流程。表达候选、回顾、自动记忆注入三个开关都开启才安排回顾。仅关闭回顾时，原有手动提出候选、审核、版本和遗忘功能仍可使用。

回顾任务只保存消息定位和正文哈希，不另存整段聊天；候选的来源摘录沿用记忆树规则，属于本机数据。批量清空会同时清理当前会话回顾状态；遗忘记忆会取消尚未完成的回顾，防止继续使用失效材料。

回顾提示与工具往返仍可能增加原聊天模型的 token；不宣称成本为零，也不保证模型每次都提交回顾。实际是否更自然，需要结合人工反馈和完整多轮上下文观察，不能用回复数量或句子变短代替质量评估。

验证：`npm run test:style-review`，使用虚构消息、临时数据库及本机 MCP/HTTP 服务，不发送真实 QQ 消息或调用收费模型。模块不提供自由改写自述文件、共享跨群记忆、额外生活线或微信原生发送能力。
